### APPR: Solution Approach

**CR-APPR-03-001 — LOW — Refetch on capture-close cannot surface the captured task**
- **Location**: `mobile/app/(tabs)/index.tsx:149`
- **Evidence**: `onClose={() => { setCaptureOpen(false); fetchTasks() }}` — but `CaptureModal` inserts tasks with `status: 'inbox'` (`mobile/components/CaptureModal.tsx:34`), while the Today screen only queries `status = 'calendar'` and `status = 'next_actions'`.
- **Impact**: The added refetch never displays the task the user just captured; it only picks up unrelated remote changes. Either the intent (show new capture) is unfulfilled, or the call is redundant.
- **Recommendation**: If the intent is freshness after capture, keep it but note that captured tasks land in the Inbox tab; if the intent was to show the captured task, no refetch of this screen can achieve that.
- **Fix capability**: `suggested_fix`

- **Impact**: CLAUDE.md states environments are built by applying `supabase/migrations/` in order. - **Recommendation**: Commit `supabase/migrations/20260527000000_add_recurrence_rule.sql` (ideally amended into or immediately following `78978b5`).

**CR-HOLISTIC-COH-01-001 — MEDIUM — Recurrence is display-only: no code path can ever set `recurrence_rule`**
