## Implementation steps

1. **Staging and foundation.** Keep Gmail off for public production users. Configure a test deployment/mailbox, apply the migration, and test connection, account ownership, and disconnect. Check whether Gmail shares a Cloud project with Calendar and handle revocation accordingly.
2. **Bring your own API key.** Add one supported LLM provider first, model selection, encrypted per-user keys, connection testing, and key removal. Use server-only calls and explicit consent to send email content. Check provider data terms against Google's Limited Use requirements.
3. **Read Inbox messages.** Retrieve bounded, paginated messages across the Gmail Inbox, including messages already present when Gmail is connected. Extract text without attachments. Do not read Spam or Trash. Treat email content as untrusted.
4. **Manual scan and suggestions.** Add Scan now, structured task extraction, source links, and a review/accept/dismiss flow. Implement atomic completion, concurrency protection, retry limits, no-action outcomes, and usage limits to prevent duplicate tasks and uncontrolled requests.
5. **End-to-end verification and disclosures.** Test with a dedicated mailbox; cover account isolation, reconnect/disconnect, duplicate scans, provider failures, malformed output, and deletion. Update privacy disclosures to match actual behavior and capture screenshots of the completed UI.
6. **Google verification and release.** Record the working staging OAuth and task flow, including the unverified-app warning. Submit accurate scope justification and the demo video; complete Google's requested review/security assessment. Enable public Gmail access after approval. Schedule automatic scans in a later phase.
